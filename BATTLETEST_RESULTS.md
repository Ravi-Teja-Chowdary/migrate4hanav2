## How to populate this file

```powershell
# Prereqs:
#   1. cd terraform\environments\prod && terraform apply -auto-approve
#   2. .\scripts\push-fargate-image.ps1

# Then run the battletest on AWS (one command):
.\scripts\run-battletest-aws.ps1 -Scale large -IncludeCodeRemediation
```

See `BATTLETEST_HOWTO.md` for full detail.

## What the populated version will contain

| Section | What you'll see |
|---|---|
| **Summary metrics** | Total records (5.5M for `large` scale), end-to-end elapsed, throughput, issues, cutover verdict |
| **Runs table** | Every battletest run ever done, sorted newest-first |
| **Per-stage detail** | Extract / transform+coverage / load / hash chain / gap-closure-stress / code-remediation / cutover-verdict — elapsed, throughput, errors per stage |
| **Gap-closure stress results** | CVI cycles detected, DAG validation, throttle exponential-backoff verification, cluster-table preflight scenarios, hash chain integrity at scale, cutover_verdict precedence across 5 scenarios |
| **Code remediation results** | AST-auto-fixed count, AI-fallback invoked count, quarantined count |
| **Cutover verdict + precedence rule** | The final GO/NO_GO verdict + the explicit rule text |

## Why this matters

This file is the **cited artefact** for the pitch deck's "Slide 8.5 —
Battle-tested at scale." When a prospective client asks *"have you actually
tested this thing?"* you point them at this report. The report cites the
AWS run by `aws_run_metadata.fargate_task_arn` so it's traceable to a real
CloudWatch log group.

Until the first AWS run completes, the pitch deck's slide 8.5 has placeholder
numbers — don't show that slide until this file is populated.
